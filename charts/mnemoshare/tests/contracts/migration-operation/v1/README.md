# Migration operation contract v1

This generated bundle is the sole current migration-operation contract. It is generated from the compiled process composition and persisted-format closure and describes the `mnemoshare-migrate` executable, its pre-1.0 reset/plan/apply/verify/status command grammar, governed process/profile IDs, persistence universes, digest transport, and the required plan-all -> down -> apply-and-verify-all -> up lifecycle.

The migration operation exclusively owns application-level schema and format evolution. Deployment adapters own explicit process down/up orchestration and must leave the application down after a committed migration failure; automatic rollback to the old writer is not permitted. The one-time `pre-1-reset-format-ledger` command requires both `--exclusive` and `--confirm-before-first-1.0`. Apply runs with `--exclusive --bootstrap-policy provision-untracked` after all application writers are drained and provisions only generated untracked carriers. `--status` atomically publishes truthful bounded progress snapshots, and `status` is the backend-neutral liveness probe; lease refreshes never count as progress. `--termination-log` receives the same strict terminal snapshot for the deployment supervisor. The supplemental SQLite process lock covers the apply command only, while the durable database lease remains authoritative; deployment orchestration owns plan/down/verify/up. `--expect-contract-fingerprint` makes the target binary attest its embedded operation grammar before persistence is opened. `--planning-mode` is part of that grammar. `--universe` selects one generated external persistence universe. `--plan` selects the immutable plan artifact, and `--expect-plan-digest` independently asserts it.

`contract.json` is the generated canonical artifact. Re-run `go run -tags migrations ./tools/migrationoperationcontract -root . -check` to verify generated state. The v1 directory remains mutable until a public release freezes it.
